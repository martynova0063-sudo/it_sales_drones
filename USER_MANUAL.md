# 📖 Инструкция по эксплуатации Программного Комплекса

## 1. Подготовка окружения и установка

Перед запуском системы необходимо подготовить компьютеры, которые будут выполнять роль Пульта Управления (ПУ) и Нод (обработчиков видео).

### 1.1. Установка внешних приложений
Система критически зависит от библиотеки обработки видео **FFmpeg**.

*   **Linux (Ubuntu/Debian):**
    ```bash
    sudo apt update
    sudo apt install ffmpeg
    ```
    
    *Проверка:* Введите `ffmpeg -version` и `ffprobe -version` в терминале. Должна вывестись информация о версиях.

*   **Windows:**
    Скачайте сборку с официального сайта, распакуйте и добавьте путь к `bin` (где лежат ffmpeg.exe) в переменные среды PATH.

### 1.2. Установка Python-библиотек
В папке проекта выполните:
    ```bash
    pip install -r requirements.txt
    ```

## 2. Настройка сети (Связь между ПУ и Нодами)

Система поддерживает два режима работы сети. Выбор режима осуществляется в файле `.env` (или `config_monitor.py`) параметром `PUBLIC_IP_PROVIDER`.

### Вариант А: Работа через Интернет (Рекомендуется: Tailscale)

Используется, если Ноды и ПУ находятся в разных местах/сетях. Используется `PUBLIC_IP_PROVIDER="TAILSCALE"`.

**Инструкция по настройке Tailscale на Linux (Ubuntu):**

1.  **Регистрация:**
    *   Перейдите на https://tailscale.com/register/ и создайте аккаунт.

2.  **Установка клиента (на всех ПК):**
    ```bash
    curl -fsSL https://tailscale.com/install.sh | sh
    sudo apt update
    sudo apt install tailscale
    ```

3.  **Авторизация и запуск:**
    ```bash
    sudo tailscale up
    ```
    *   Скопируйте ссылку из терминала, вставьте в браузер и нажмите **"Connect"**.
    *   Повторите это на **всех** компьютерах (ПУ и все Ноды). Все они должны быть в одной Tailscale-сети.

4.  **Проверка:**
    Выполните команду:
    ```bash
    tailscale ip -4
    ```
    Вы увидите адрес вида `100.x.y.z`. Устройства должны "пинговать" друг друга по этим адресам.

5. Подробная инструкция по установке и настройке соединения через **tailscale** находится в файле [tailscale_instruction.md](tailscale_instruction.md)

### Вариант Б: Работа в закрытой локальной сети (LAN)

Используется, если все устройства подключены к одному роутеру или коммутатору без доступа извне.

   1.  В файле `.env` установите: `PUBLIC_IP_PROVIDER="LOCAL_ONLY"` (или `"STATIC_IP"`).
   2.  Убедитесь, что порты **9000** (ПУ) и **8001, 8002...** (Ноды) открыты в локальном фаерволе.

## 3. Настройка конфигурации

### 3.1. Способ обнаружения Пульта (Service Discovery)

Чтобы Нода знала, куда отправлять тревоги, используется два метода (настраиваются в `config_monitor.py`):

*   **Telegram (Автоматически):**
    *   ПУ при запуске отправляет свой адрес в специальный Telegram-канал и закрепляет сообщение.
    *   Нода читает закрепленное сообщение и узнает адрес ПУ.
    *   *Требует:* `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHANNEL_ID` в `.env`.

*   **Файл (Вручную/Локально):**
    *   ПУ записывает свой адрес в файл `configs/connection.txt`.
    *   Если Нода запущена на том же ПК или имеет доступ к этому файлу (через сетевую папку), она берет адрес оттуда.

### 3.2. Настройка камер (`configs/stream_sources.json`)

В этот файл вносятся данные о камерах. Пример:

```json
{
  "cameras": [
    {
      "id": "cam_1",
      "name": "Камера на КПП",
      "page_url": "rtsp://admin:pass@192.168.1.55:554/stream1",
      "source_type": "RTSP"
    },
    {
      "id": "drone_feed",
      "name": "Поток с дрона",
      "page_url": "rtmp://192.168.1.100:1935/live",
      "source_type": "RTMP"
    }
  ]
}
```

    *   id: Уникальный идентификатор (используется при запуске Ноды).
    *   page_url: Прямая ссылка на поток (RTSP, RTMP, HTTP/HLS).
    *   source_type: Тип источника: "RTSP", "RTMP", "HLS", "FILE".

## 4. Запуск системы
### 4.1. Запуск Пульта Управления (ПУ)

На центральном компьютере выполните:
    ```bash
    python3 app.py
    ```

Интерфейс будет доступен в браузере по адресу: http://localhost:9000 (или по Tailscale IP на другом ПК).

### 4.2. Запуск Ноды (Обработчика)

На компьютере, к которому подключена камера (или на том же):
    ```bash
    python3 node.py --select <ID_КАМЕРЫ> --stream_port <ПОРТ>
    ```

*   --select: ID камеры из файла stream_sources.json (например, cam_1).
*   --stream_port: Порт для вещания видео на ПУ (по умолчанию 8001). Если запускаете несколько нод на одном ПК, меняйте порт (8002, 8003...).

Автоподключение: Нода сама найдет ПУ (через Telegram или файл) и зарегистрируется на нем. При потере связи она будет пытаться переподключиться.

## 5. Возможности Пульта Управления (Интерфейс)
### 5.1. Галерея камер

*   Отображает миниатюры всех подключенных активных Нод.
*   Индикация:
    *   🟢 (Зеленый): Нормальная работа.
    *   🔴 (Красный): ТРЕВОГА (обнаружен объект).
    *   🟠 (Оранжевый): Предупреждение (нет сигнала более 35 сек).
    *   ⚫ (Серый): Оффлайн (нет сигнала более 60 сек).

    Управление видом: Кнопки **"4 окна"**, **"8 окон"**, **"16 окон"** меняют сетку галереи.

### 5.2. Главный монитор и работа с алертами

*   При клике на камеру в галерее или при приходе алерта, информация выводится на главный экран.
    *   **Статус**: Текущее состояние (Активен/Тревога), время последнего обновления.
    *   **Информация**: Списки **"Все классы модели"** (что умеет искать нейросеть) и **"Целевые классы"** (что мы считаем угрозой).
    *   Кнопка **"Подробнее..."**: Включает режим **"Лупы"** (показывает увеличенный кроп обнаруженного объекта) и раскрывает детальную информацию о классах.
    *   Кнопка **"Запросить видео"** / **"Показать картинку"**: Переключает режим отображения:
    *   *   **Картинка**: Обновляемый статический кадр (экономит трафик).
    *   *   **Видео**: Живой MJPEG-поток с Ноды с отрисовкой детекции (рамок).
    *   Кнопка **"Сброс тревоги"**: Вручную снимает статус тревоги с камеры (цвет возвращается на зеленый).

### 5.3. Работа с архивом
*   Если была зафиксирована **тревога**:
    *   Появляется кнопка **"Скачать архив"**.
    *   При нажатии ПУ отправляет запрос на Ноду. Нода формирует видеофайл, охватывающий момент тревоги (плюс время до и после).
    *   Файл скачивается на компьютер ПУ.
    *   В поле **"Статус файла"** отображается путь к сохраненному файлу.
    *   Кнопка **"Открыть папку с архивами"** открывает системный файловый менеджер в папке, куда сохраняются все видео.

### 5.4. Уведомления
*   Чекбокс **"Отправка уведомлений в Telegram"**: Этот переключатель управляет дублированием тревог.
    *   **ВКЛ:** При обнаружении угрозы система немедленно отправляет в ваш Telegram-чат фотографию объекта с указанием класса, вероятности (confidence) и времени обнаружения.
    *   **ВЫКЛ:** Алерты отображаются только в интерфейсе Пульта Управления.
    *   *Примечание:* Для работы этой функции убедитесь, что в файле `.env` прописаны корректные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

## 6. Решение частых проблем (Troubleshooting)

*   **Нода запущена, но не появляется в Галерее ПУ:**
    1.  Убедитесь, что Пульт Управления был запущен *раньше* или работает в данный момент.
    2.  Проверьте подключение к сети (Tailscale или локальная сеть). Введите `tailscale status` в терминале на обоих устройствах — они должны быть `active` и видеть друг друга.
    3.  Посмотрите в логи Ноды (терминал, где она запущена). Должна быть строчка: `INFO - Обнаружен адрес ПУ...`. Если её нет, Нода не может найти Пульт.

*   **Видеопоток черный или с артефактами:**
    1.  Проверьте ссылку на камеру (URL) в VLC-плеере на том же компьютере.
    2.  Убедитесь, что в `stream_sources.json` верно указан `source_type` ("RTSP" для IP-камер).

*   **Не скачивается архив:**
    1.  Кнопка "Скачать архив" активна только тогда, когда камера находится в режиме "ТРЕВОГА" (Красная рамка).
    2.  Убедитесь, что на диске компьютера с ПУ есть права на запись в папку `downloaded_archives`.

## 7. Завершение работы
Для корректной остановки компонентов системы:
1.  Перейдите в терминал, где запущен процесс (Нода или ПУ).
2.  Нажмите сочетание клавиш **Ctrl + C**.
3.  Дождитесь сообщения `Stopping node...` или остановки сервера. Это гарантирует, что все видеофайлы будут корректно сохранены и закрыты.
